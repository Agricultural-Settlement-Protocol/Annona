## What this is

**Annona** is an agricultural offtake **settlement protocol** on Stellar/Soroban for Indonesia's Koperasi Desa Merah Putih (KDMP) and, generically, any commodity cooperative. It turns the input-credit to harvest-buyback (*yarnen*) loop into a tamper-proof, auto-netting, HPP-anchored on-chain ledger.

Built for the **APAC Stellar Hackathon 2026** (submit 15 Jul), then the **Stellar Community Fund** Build track.

**The one-line mental model:** we ship one app (KDMP-facing), but architect a protocol (a reusable offtake settlement standard). UI feels like a KDMP app; contracts feel like infrastructure others build on.

## Golden rules (do not violate)

1. **PII never touches the chain.** KTP, names, phone, GPS go to Postgres only. On-chain stores hashes, amounts, status, grades, counters. Always hash KTP before anchoring.
2. **Chain only where it earns its place.** On-chain means (a) tamper-proof settlement record, (b) auto-netting, (c) reputation/receipts. Everything else is a normal web app. Don't put web2 things on-chain "because blockchain."
3. **Never claim "autonomous settlement" or "blockchain pays the farmer."** Crypto is illegal as payment in Indonesia. Correct framing is **"tamper-proof settlement record."** See `ARCHITECTURE.md` section 5 (three settlement paths).
4. **The yield estimate is a transparent formula, never "AI prediction."** `expected_vol = area × yield/ha`, with the BPS/KATAM source shown.
5. **Shared types live in `packages/core`.** Contract event shapes, `Agreement`, `Status`, and similar. `web`, `api`, `sdk` import from there and never redefine. Prevents drift between contract and dashboards.
6. **Settlement is a three-way split, debt netted first.** `net_to_farmer = max(0, (gross - handling_cut) - input_debt)`. The collected debt splits into **Supplier principal residu** + **KMP margin** (on-chain, separately tracked). Debt cleared before the farmer sees positive cashflow. Protects the coop AND the Supplier's principal. See `SMART-CONTRACT.md` §5. (Post-4b: the input-principal party is **Supplier**, code + UI; PT Agrinas is the real-world entity that fills it, and the physical **warehouse operator** — "gudang Agrinas" — is a separate infra role that keeps the "Agrinas" name.)
6b. **Residu principal is the Supplier's money, not KMP's.** KMP holds it in pre-funded cash until remitted; the on-chain split-allocation + `confirm_remittance` reconciliation is the anti-moral-hazard guarantee. Never let the docs/UI imply KMP owns the residu principal.
6c. **Three parties, two gates.** Supplier (operator) ↔ KMP (koperasi) ↔ Farmer, + read-only Government. `dispatch_supply` (Supplier) then `accept_supply` (KMP) must both fire before debt is active. "KMP" is the primary term; KDMP is the flagship instance.
7. **Flags indicate, humans decide.** `Suspected` and similar are never automatic accusations. The officer/auditor resolves.

## NOTES (hard product/UX constraints)

- **NO EM DASHES IN UI.** Never render an em dash (—) in any user-facing string, label, copy, toast, or AI output shown to users. Use a comma, a period, parentheses, or the word "to" for ranges. This applies to all Bahasa and English UI text and to AI assistant responses. (Docs/code comments may use them; the rendered UI may not.)
- Bahasa Indonesia is the default UI language; English is a toggle.
- Every on-chain action in the UI shows a tx hash plus an explorer link.
- Money shown to users is formatted rupiah (e.g. `Rp14.900.000`), never raw smallest-unit integers.
- UI must stay legible to non-expert village officers: big numbers, color-coded statuses, plain Bahasa.

### 2026-07-13 — Merging `dev` into `feat/v4-migration`: the wire/DB layer split collided, and only `basePrice` is genuinely asymmetric
- **What:** The two branches solved the SAME v4.0 rename from opposite ends. `feat/v4-migration` had the **contract** and synced only the WIRE layer, deliberately bridging to still-`agrinas` DB columns. `dev` had no contract, but landed the **whole read-model** (Phase 4b rename on live Supabase + Phase 5 funding/subsidy/payable). Typecheck could never catch that — both names compile fine; the field would simply arrive `undefined` from a real chain event and NULL out the column post-deploy. dev also re-declared `export type SubsidyTier` in `events.ts`, colliding with the real one in `status.ts` via `index.ts`'s `export *`.

Anchor every event field to the emitting `.rs` struct + the `poll.ts` decode path (hand-listed `#[topic]` fields vs `deepCamel`'d value-map keys); a branch that lacks the contract has no authority over wire names, no matter how internally consistent it is. ### 2026-07-12 — Financier auth 500 was a malformed auth.users row, not a wrong password; ternary refactor left a dangling `)}`; heredoc stdin gotcha
- **What:** Three separate bugs in one session. (1) Financier login failed with UI text "Email atau kata sandi salah" but the real Supabase response was `500 {"error_code":"unexpected_failure","msg":"Database error querying schema"}` — the earlier ad-hoc `auth.users`/`auth.identities` insert (see the 2026-07-11-ish entry on financier auth user creation) had left token columns (`confirmation_token`, `recovery_token`, etc.) NULL instead of `''`, which makes GoTrue's Go scanner fail on login for that one row. The `/auth` page's `catch` block collapses every `signInWithPassword` error to the same "wrong credentials" string, so a 500 schema error and an actual bad password are indistinguishable in the UI. (2) Converting a `{cond && (<Card>...)}`-wrapped section to an always-rendered `<Card>` with an internal `{!cond ? <Empty/> : (...)}` ternary left the OLD closing `)}` orphaned after the new `</Card>`, which is valid enough to not immediately fail `tsc --noEmit` in isolation but breaks Next's SWC parser at `next build` with `Unexpected token`. (3) A statusline script piped JSON via `stdin` into `python3 - <<'PY' ... PY` — a heredoc REPLACES the command's stdin with the heredoc body, so the piped data never reaches the script; `json.load(sys.stdin)` then fails on an empty string.
- **Fix:** (1) Diagnosed by testing the Supabase Auth REST endpoint directly with `curl .../auth/v1/token?grant_type=password` for both the broken account and a known-good one (kmp@) — the 500 vs 200 response proved it wasn't a credentials issue. (2) Fixed by deleting the stray `)}`; added a manual paren-balance check (`node -e` walking the file counting `(`/`)`) before trusting `tsc`/build. - **Rule:** When a login/auth error message is generic ("wrong credentials"), verify against the raw provider response (curl the token endpoint) before assuming it's a password/seed-data issue — GoTrue 500s on a malformed `auth.users` row read identically to "wrong password" in a generically-worded UI. Any raw SQL that creates `auth.users` rows must set every token column to `''`, never leave it NULL/default. When manually converting a JSX `{cond && (...)}` block into an always-rendered section with an internal ternary, count the closing parens/braces before and after — `tsc --noEmit` does not reliably catch an extra top-level `)}`, only `next build`'s SWC parser does; always run a full `pnpm build` (not just typecheck) after this kind of refactor, on this or any repo. Never combine a stdin pipe with a `<<heredoc` on the same command — the heredoc wins and the piped data is silently lost; capture stdin to a variable first if the command also needs a heredoc.

## Conventions

- **TypeScript strict** everywhere. No `any` without a comment justifying it.
- **Imports:** internal packages via `@annona/core`, `@annona/sdk`, `@annona/ui`.
- **Money:** integers in smallest unit (rupiah-cents). Never floats for money. Volumes in **grams** on-chain.
- **Bahasa first** in UI strings, English toggle via `next-intl`. Code/comments in English.
- **Env:** never commit keys. `.env.local` (web), `.env` (api). Testnet keys only.
- **Indexer idempotency:** events keyed by `(tx_hash, event_index)`.
- **Lint/format:** Biome (single tool). Run before commit.

## Stellar specifics

- Network: **testnet** for MVP. Soroban RPC plus Horizon public endpoints.
- Wallet: **Freighter** (`@stellar/freighter-api`), supports `signAuthEntry`.
- Token: **dIDR** via SAC (SEP-41 compatible). Settlement asset.
- On-chain reads via `@stellar/stellar-sdk` (13.x). Contract reads exposed through `@annona/sdk`.
- Don't hand-roll tokens/oracles/lending. Reuse SAC, Reflector, Blend, DeFindex. See `INTEGRATIONS.md`.
- When writing the contract (later): `require_auth()` on writes, TTL-extend every public fn, emit events (mandatory).
